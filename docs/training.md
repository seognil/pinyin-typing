# 训练

## 训练目标

- 词语打字是主要训练流程。
- 单字训练负责覆盖、诊断和补强。
- 训练体验应体现渐进性，而不是把所有词一次性摊平。

## 课程分层与训练范围

当前词语课程主干为：

- `edu-1`
- `edu-2`
- `edu-3`
- `edu-4`
- `modern`
- `phrase`

运行时应先按用户选择缩小训练范围，例如：

- 词长：如 `2-character`
- 课程层级：如 `edu only`、`edu + modern`
- 可选混淆过滤：如某一类读音专项

这一步得到的是训练子集，而不是最终训练单元。

## 掌握度模型

未来运行时状态需要同时记录：

- 字级掌握度
- 词级掌握度

最小方向上，训练单元至少记录：

- `seen`
- `correct`
- `wrong`

词语作答结果应能反哺单字掌握度。这样当一个词中部分字已熟、部分字未熟时，运行时能够看见这种差异。

## 训练子集之后的业务分桶

当前初步讨论的业务分桶是：

- `半熟`
- `全生`
- `已打`

理解方式：

- `半熟`：词本身或词内的字处于部分熟悉状态
- `全生`：词和词内字基本都还没打过
- `已打`：已经进入过训练历史的词，后续还可以再细分成错词、熟词等复习类型

这些分桶不是静态标签，而是会随着训练推进不断变化。

## 选词策略初稿

当前讨论到的方向是：

- 先根据课程分桶、词长、可选混淆过滤得到训练子集。
- 训练子集随后动态拆分成 `半熟`、`全生`、`已打` 等业务分桶。
- 每批训练优先给 `半熟 + 全生` 留出大部分容量。
- 剩余容量再由 `已打` 项补位。

这样做的目的：

- 保持课程推进
- 避免训练完全退化成复习
- 又不会因为只推新词而丢掉巩固

## 随机性与窗口

虽然词语有统一的全局 `fr`，但训练不应机械按 `fr` 逐条播放。

当前方向是：

- 在训练子集的头部维持一个滑动窗口
- 每个业务分桶内部都使用加权随机
- 不同分桶之间再按容量分配组合成本批训练单元

这意味着：

- `fr` 提供整体推进方向
- 业务分桶提供训练阶段感
- 加权随机保证体验不是死板背列表

## `fr` 在训练中的作用

- `fr` 负责提供统一的基础顺序
- 它可以帮助运行时定义“头部窗口”和“推进方向”
- 但 `fr` 不是唯一选词依据

后续真正采样时，还需要结合：

- 字级掌握度
- 词级掌握度
- `半熟 / 全生 / 已打` 分桶
- 错误情况和复习需求

## 当前未定事项

以下内容已经有方向，但还没有冻结成最终规则：

- `半熟 / 全生 / 已打` 的精确定义
- `已打` 内部如何继续拆分成错词、熟词等复习类型
- 每批训练中各分桶的精确配额
- 加权随机的精确公式
- 滑动窗口大小和推进速度

这些细节留到运行时开发阶段继续细化。
